# 03. s-node 장애 복구 시간(MTTR)

**목적:** Kubernetes Lease로 active-standby를 하는 s-node 중 활성 pod가 죽었을 때, 시스템이 다시 합의할 수 있게 되기까지의 시간을 잰다(NOTES §48~§49).

**MTTR의 정의:** 장애 발생부터 **모든 w-node가 새 커미티를 받아 합의를 다시 할 수 있을 때까지**다. w-node 재등록까지 포함한다.

## 세팅

| 항목 | 값 |
|---|---|
| 구성 | s-node pod 3개(활성 1 + 대기 2), w-node 10개(로컬 Kubernetes) |
| 장애 유형 | 정상 종료(pod 삭제), 강제 종료(SIGKILL), 멈춤(SIGSTOP) |
| 반복 | 장애 유형마다 10회 |
| 비교 | 예전 설정(Lease 6 s 등) / 지금 설정(Lease 2 s + 수정) / 참고로 Lease 1 s |

## 결과

| 장애 | 예전 (Lease 6 s 등) | **지금 (Lease 2 s + 수정)** | 참고: Lease 1 s (기각) |
|---|---|---|---|
| 정상 종료 (pod 삭제) | 5.1 s, 1회 복구 실패 | 5.6 s, 10/10 | 4.0~5.1 s |
| 강제 종료 (SIGKILL) | 10.8 s (6.6~12.2) | **5.4 s (4.6~5.9)** | 2.9~4.3 s |
| 멈춤 (SIGSTOP) | 11.8 s (11.4~12.7) | **5.4 s (5.0~6.3)** | 3.5~4.3 s |
| 활성 전환만 (재등록 제외) | 0.6 / 5.9 / 6.8 s | 0.5 / 2.1 / 2.2 s | — |

- **지금 설정:** Lease 2 s / 갱신 1.5 s / 재시도 0.5 s, 조기 커미티 구성(유예 3 s), w-node 재접속 1 s. 10분 무장애 관찰과 1시간 37분 부하 동안 잘못된 전환이 0회였다.
- **Lease 1 s:** 부하에서 잘못된 전환과 pod 재시작이 생겨 기각했다.

## 폴더

- **`scripts/`**
  - `mttr.sh`: 한 설정의 장애 유형별 반복 측정. `OUT=<폴더> CONFIG=new|old|… TRIALS=10`
  - `run-all.sh`: 예전 대 지금 설정
  - `run-12.sh`: 유예 1 s / Lease 1 s 변형
  - `supplement.sh`: SIGSTOP 보충
  - 결과 폴더 기본값 `R=`가 개발 PC 경로라서 실행할 때 바꿔야 한다.
- **`data/mttr-1017/`**: 예전·지금 설정의 시행별 기록. `all.csv`가 전체 요약이다.
- **`data/mttr-1019/`**: 2026-10-19 재측정(지금 설정, 유형마다 10회). 중앙 MTTR: pod 삭제 4.79 s, SIGKILL 4.49 s, SIGSTOP 5.77 s(06 참고)
- **`data/mttr-1017b/`**: 유예 1 s(g1), Lease 1 s(l1), 둘 다(g1l1)
